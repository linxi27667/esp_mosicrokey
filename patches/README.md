# 上游适配补丁

基线提交见 `upstream-lock.json`，补丁应用后的全部源码 SHA256 见 `source-manifest.json`。
`scripts/verify-sources.py` 校验当前工程内的源码，不读取原快照所在目录。

`provenance.json` 记录六个实际修改文件在固定上游提交的原始哈希与产品哈希。`scripts/verify-patches.py` 将当前补丁反向应用到构建目录的临时源码，再逐字节比对原始哈希；正常构建与打包都会运行，不依赖网络。校验显式关闭本次 Git 操作的 Windows autocrlf，避免换行转换掩盖差异。

## 小智

`xiaozhi-mosicrokey.patch` 基于 `ed5cd7ba0011dc06fefd0762790857268c41b430`，已经应用到 `third_party/xiaozhi`，不要再次应用。

- `application.h/.cc`：增加可调度的停止会话入口；语音、唤醒词、迟到的 TTS 回调检查前台焦点；关闭产品固件的自动升级及主动升级入口，保留激活、协议协商与版本查询。
- `audio/audio_service.cc`：失去焦点时禁止采集处理、音频测试和播放；丢弃迟到的解码包。
- `assets.cc`：产品 UI 使用自己的完整中文字体，不向服务端请求上游动态字体推送。

构建入口、语言与音频资源生成、板工厂及显示桥接都放在项目组件与脚本中；没有修改上游根工程脚本，也没有编入原始 `app_main` 或其他板工厂。

## ESPClaw

`espclaw-glm-auth.patch` 基于 `74b18700a1d6c40de472bfc71c19e49356ca1cc0`，已应用。

- HTTPS 请求使用非阻塞轮询检查取消和整体超时；v0.1.8 在 TLS 连接事件中将单次 I/O 等待设为最多100 ms，在断开事件中恢复原连接预算。事件处理先于取消检查，兼容 SDK 忽略回调返回的行为；重连不重置整请求期限。DNS/TCP 建立仍依赖 SDK，不宣称所有网络阶段均为100 ms取消。异步请求避开上游把 EAGAIN 当失败重试的 HTTP 连接池。
- v0.1.9 仅在异步 client 保持 HTTP_STATE_REQ_COMPLETE_HEADER 时，将部分/暂未就绪的正文 WRITE_DATA 视为等待，从原已保存偏移续传；不新建连接或重新发整次 POST。关闭/请求头/负值写失败保留错误，取消和整请求期限仍有效。实际传输源码48项主机注入覆盖这些边界。
- 智谱 Bearer 鉴权失败返回 401 且不提供 WWW-Authenticate；保留真实鉴权原因，避免被 ESP-IDF 的 Basic/Digest 协商错误掩盖。
- 兼容后端发送工具时明确设置标准 `tool_choice=auto`。实测 GLM 在此配置与明确工具指令下返回原生工具调用；不能据此保证每次模型输出都会遵从指令，仍需检查执行结果。
- 只对明确的 429/503 响应做最多两次重试（4/8 秒退避），共享原始每轮超时预算；取消可中断退避，401、超时或不明确的网络失败不重试。迟到的 HTTP 200 也被期限检查丢弃，避免在期限后执行模型工具。已执行的游戏工具不会因 HTTP 重试而重新执行。真实后端的主机故障注入覆盖恢复、次数上限、取消、迟到响应和总期限；设备日志仍需区分外部服务限流与固件错误。

工具、USB 临时游戏预览、配置、上下文与密钥脱敏均在项目适配器内，通过公开的能力与上下文接口扩展。
