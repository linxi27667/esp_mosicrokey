## 实板与服务验收（逐项以实板记录为准）

| 顺序 | 操作及通过条件 | 必须保存 |
|---|---|---|
| 1 | 确认 COM、S31 型号/板卡修订、Flash/PSRAM；启动无持续复位 | 启动日志与固件 SHA256 |
| 2 | 检查 RGB565 五色/边界、横屏、偏移、亮度；八按键、旋钮按压和正反转/正常速度去抖；电脑两组动作及休眠/重连 | 照片/日志/接线与参数，区分模拟 ACK 和实际电脑执行 |
| 3 | FAT32 TF 启动挂载、demo 安装、重启发现、游玩、重开、退出 | 目录、清单与串口记录 |
| 4 | 小智配网、激活、录音、回复播放、确认中断、离页停止采集与播放 | 真实服务和音频状态日志 |
| 5 | 兼容 API 请求/回复/取消、五项 TF 工具及临时 game_preview；AI 创作和修改真实安装 | 脱敏 HTTP/工具结果与 TF 清单 |
| 6 | 错误密钥、60 秒超时、断网重连、缺卡、空间不足、读写失败、拔卡/重挂 | 每项故障与恢复日志 |
| 7 | 小智对话时 Agent 后台工作；游戏时后台创作/安装，当前版本保持 | 焦点、版本及 FPS 日志 |
| 8 | 连续两小时、切换 100 次、反复游戏加载退出，无崩溃/WDT/持续内存增长 | 完整日志、最低堆和栈水位 |
| 9 | 默认游戏 30 FPS，后台创作时持续不低于 20 FPS，任务栈至少余 30% | 相应场景 FPS/栈记录 |

包校验失败必须可回传 Agent 修正；首次失败后最多三次修正。Lua 初始化 100 ms、每帧 10 ms、100000 指令、256 KiB 堆等限制需在设备上补测耗时及异常恢复。主机时间测量只覆盖主机。

仅 USB 时可先测试明确标注的 RAM 临时预览。必须保留实际模型工具日志、导出设备源码并回放玩法、校验设备画布；不能把它当成 TF 安装或屏幕实测。`scripts/device-soak.py` 在实际游戏上执行 100 次加载退出与两小时后台 API 并发，记录完成状态、帧率、任务栈和堆趋势；脚本通过范围不包含小智语音或实体外设，堆趋势还须结合瞬时 TLS 分配审查。

设备异常后记录复位原因并使用 release/mosicrokey.elf 对应镜像分析。更改屏幕/音频/PSRAM 参数后重建并更新固件哈希，不把不同镜像的通过结论混用。
