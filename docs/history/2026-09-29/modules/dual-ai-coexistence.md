# 双 AI 功能共存

- 状态：产品要求明确，集成方案待验证
- 关联需求：`AI-CO-01`、`AI-CO-02`

## 1. 目标

在同一 MosiCrokey 设备和同一产品固件中提供小智 AI 与 ESPClaw。设备用户无需更换固件即可进入两项功能。它们共享设备硬件，但产品入口和职责可区分。

## 2. 职责草案

- **小智 AI**：面向用户的 AI 对话体验；板级音频/显示适配、服务端连接和通信协议取决于核实后的 Xiaozhi 上游。
- **ESPClaw**：设备端 Agent/Chat Coding 体验，尤其负责创建或修改设备游戏。
- **设备入口**：让用户选择/返回两种 AI 功能和游戏库，并显示网络、存储和运行状态。

这份职责分配是产品级划分，不代表将采用某个上游仓库的内部模块名称或入口实现。

## 3. 生命周期与共享资源

需设计下列接口；具体所有权和调度方式待架构评审：

- 页面/焦点：当前前台功能、返回系统入口、游戏启动和退出。
- 键盘/控制器：活动功能获得输入焦点；游戏按键映射不能意外触发 AI 界面命令。
- 显示：主界面、对话/Agent 页面和游戏界面之间明确切换。
- 音频：小智语音输入/播报与游戏音效之间的音频焦点、打断和静音行为。
- 网络：联网状态、服务认证、请求超时和断网提示。
- 存储：Agent 内容与游戏包的目录/权限隔离，禁止游戏任意读写 Agent 凭据和系统配置。
- 资源：双 AI、游戏和显示/音频在 RAM/PSRAM/Flash/CPU 上的占用需实际测量。

“同时搭载”目前保证同固件和同设备中都可用；后台并行处理、游戏中语音唤醒、同时生成游戏和运行其他游戏尚未列为已确认行为。

## 4. 错误与降级

- 某个外部模型服务不可用时，另一项已集成功能仍能显示自己的状态和错误信息。
- 切换功能不能导致设备入口丢失或要求重新烧录固件。
- 资源不足、无线断连、音频设备不可用和任务异常的提示/恢复策略需在实测后补齐。

## 5. 验收场景

1. 单一固件镜像在目标板成功构建、烧录和启动。
2. 用户从设备界面进入小智 AI 并完成一次可配置服务上的对话。
3. 用户返回入口并进入 ESPClaw 完成一次 Agent 交互。
4. 两项功能无需重新刷固件即可反复切换；若切换需要重启，必须经用户确认并记录为限制。
5. 对话/语音、游戏和网络并发场景按产品确定的矩阵实测并记录资源结果。

## 6. 待确认

- ESPClaw 的准确上游仓库与版本：当前调研以 [espressif/esp-claw](https://github.com/espressif/esp-claw) 为参考。
- 小智的准确版本、构建配置与目标板支持。
- 首屏如何呈现两项功能，设备是否支持触摸。
- 两个 Agent 的后台生命周期和音频焦点规则。
- 模型服务如何配置、凭据保存和断网后最低可用能力。
