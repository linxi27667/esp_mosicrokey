# 验证计划

- 状态：初版框架
- 目标板级验证：尚无记录

验证分为构建与硬件启动、双 AI 集成、TF 游戏闭环和资源/并发评估。芯片规格、上游 README 或模拟器结果都不能代替 MosiCrokey 目标板实测。

## 验证记录格式

每项记录包含：编号、需求/风险、硬件型号与修订、ESP-IDF/依赖提交、操作步骤、预期结果、实测结果、日志/数据位置、状态和日期。

状态使用：待定义、待验证、通过、失败、受限/需决策。

## 阶段验证清单

| 阶段 | 验证内容 | 进入条件 | 验收记录 |
|---|---|---|---|
| 0 需求/硬件基线 | 规格来源、板级接口、MVP 和验收条件 | 硬件方案开始收敛 | 更新需求和 `board-contract.md`，明确 TF 接口 |
| 1 工具链/板卡 | IDF 配置、构建、烧录、启动日志 | 目标板确定 | 可复现步骤、板卡修订、依赖提交、构建日志 |
| 2 基础交互/TF | 键盘、屏幕及 TF 挂载、读写、目录枚举 | 板级接口确定 | 重启持久性、空间不足、拔卡/读写错误处理 |
| 3 同固件双 AI | 小智 AI 与 ESPClaw 编入同一固件并可进入 | 上游版本/许可和 IDF 组合核验 | 单一镜像提供两功能；无需刷固件即可访问；记录内存和外部服务依赖 |
| 4 ESPClaw 游戏闭环 | ESPClaw 创作/修改、保存 TF、发现、启动、游玩、退出 | 游戏包与运行时原型确定 | 重启后游戏仍可发现并运行；坏包、空间不足和写入中断有明确处理 |
| 5 游戏开发工作流 | 模板、引擎 API、模拟器/Host 验证和设备测试 | 游戏运行环境初步稳定 | 至少一个可重复生成、验证、安装的示例；设备实测记录 |
| 6 并发/集成 | 双 AI、游戏、显示、音频、网络和外设组合 | 单项验证完成 | 测量内存、响应、帧率、音频中断、功耗和稳定性；定义支持的并发模式 |

## 当前首批验证重点

目标板尚未确定，目前没有已通过的板级验证记录。优先事项：

- 核实选定板卡、`esp32s31` target 和 ESP-IDF 版本的构建/烧录/启动路径。
- 测试锁定版本的小智与 ESPClaw 能否在同一固件工程构建，记录冲突和资源占用。
- 验证 TF 卡真实接口、吞吐、持续写入、掉电/移除行为和持久性。
- 验证 ESPClaw 生成的样例游戏包可在设备写入 TF、重启后被发现并启动。
- 比较候选游戏运行时在目标分辨率、输入和音频下的性能及资源用量。
- 按用户选择的并发模式测量两项 AI、游戏、显示、音频和无线的组合行为。

ESP-Mosaico 的 PC 模拟器流程可作为游戏测试工作流参考；模拟通过不代替 MosiCrokey 目标板验证。
